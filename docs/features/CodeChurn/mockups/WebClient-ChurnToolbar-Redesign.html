Component shape

One state object, one derived query. Every control reads and writes the same slice, which is what keeps the URL shareable.

// churnQuery.ts — the whole toolbar state
type ChurnQuery = {
  scope: {
    branch: string;          // W3
    baselineBuild: string;   // W4
    targetBuild: string;     // W4
    components: string[];    // [] = all
  };
  range:
    | { mode: 'build' | 'week' | 'release' }
    | { mode: 'custom'; from: string; to: string };
  filters: {
    context:  ('runtime'|'config')[];
    author:   ('human'|'automated')[];
    workItem: ('bug'|'story'|'ims')[];
    unmappedOnly: boolean;
  };
};

Serialise it to the query string so a filtered view can be pasted into a bug. Today none of this survives a refresh.

Wrapping rule

The whole layout fix is three declarations. Worth stating plainly because it is easy to lose in a refactor.

.bar   { display:flex; flex-wrap:wrap; row-gap:9px; }
.unit  { display:inline-flex; white-space:nowrap; }
.unit  { flex:none; }

/* A unit is one label + one chipset.
   Flex may break between units.
   It can never break inside one. */

Shared with the desktop ribbon

These two apps stay separate, but three definitions should come from Core so they cannot drift: the compare-pair semantics, the four range presets, and the filter axis enums. If Runtime means one thing in WPF and another here, the counts stop agreeing and both surfaces lose trust.

Three things I assumed

Human onlyRead as commit authorship — real people versus build agents and version-bump bots. Hence the Human / Automated pair with a count on Automated. If it means manually classified rather than machine mapped, it belongs in the Coverage axis instead.
(all branches)Left as the default, but churn between two builds implies a single branch. If this genuinely spans branches, W4 needs a branch qualifier on each build or the comparison is undefined.
Automated countShown as 112 to make the point that a count on an unselected chip tells you what you are currently excluding. If that number is expensive to compute, drop it rather than compute filtered totals on every keystroke.
