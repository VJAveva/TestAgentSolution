Region reference R1–R14, for the Copilot implementation prompts

RRegionWPF controlBehaviour and binding
R1Tab stripRibbonTabItem ×5Analysis holds churn commands. Regression, Work items, Report and Settings absorb everything that used to fight for space on one row. Selected tab persists per session.
R2Scope groupRibbonGroup, SizePriority=0Never collapses. Absorbs the old Branch group and Focus group entirely. Group width flexes; three stacked rows.
R3Branch pickerRibbonComboBox editableBound to ScopeVm.SelectedBranch. Editable so a branch can be typed, matching the web form. Changing it reloads the build list in R4 and clears R5.
R4Compare pair2 × RibbonComboBoxBaselineBuild → TargetBuild. Driven by R6: a preset writes the baseline, Custom unlocks both. This is the fix for "compared to what?" — currently only inferable from the status text.
R5Component / Subsystem2 × RibbonComboBox multi-selectReplaces the unlabelled "Comp" pair. Header shows All 36 when unfiltered, 3 of 36 when narrowed. Subsystem list is filtered by the component selection.
R6Range groupRibbonGroup, SizePriority=2Merges Track changes and Timeline. Presets apply on click — no Apply round-trip. Date fields stay visible but disabled until Custom, so the mode is legible without a click. Apply only appears in Custom.
R7Deployment contextToggleButton ×2Runtime and Config carry their live counts, so the RUNTIME 23 / CONFIG 15 chips no longer need a separate status strip. "Human only" moves to R9 where it is actually a coverage question.
R8Work item axisToggleButton ×3Bug / Story / IMS. Was a separate group; it is one filter axis and belongs with the others. Multi-select, OR within the axis, AND across axes.
R9Coverage + ClearToggleButton + Hyperlink"No suite mapped" is the single most acted-on filter in this workflow, so it gets its own row. Clear resets all three axes and is disabled when nothing is on.
R10Group rowsListBox as radio stackWas "All files / Subsystems" inside Show, mixed in with filters. It is a grouping mode, not a filter — separating the two axes is what removes the ambiguity. Adds By suite.
R11DispatchRibbonButton LargeSizeThe only filled button in the ribbon. Caption shows the live selection count so the blast radius is visible before the click. Disabled at zero selection with a tooltip naming the reason.
R12Export / EmailRibbonSplitButton ×2Export ▾ gives CSV, XLSX, impact-map JSON. Email ▾ gives Send now and Manage recipients — this is where the emailed-report behaviour becomes a command instead of a status message.
R13Quick accessQuickAccessToolBarRefresh sits here because it applies to every tab, not just Analysis. The ⋯ overflow catches anything a narrow window pushed out.
R14Context barStatusBarLabelled key/value cells with dividers instead of a run of dot-joined fragments. Counts that a control already shows are not repeated here. Right side is reserved for the last completed action.

Layout budget

Fixed widths total 928 px, leaving Scope to flex. At 1280 px Scope gets 352 px, its declared minimum, so nothing scrolls. Below that, collapse priorities fire in order: Group rows, then Filter, then Range.

Open questions for you

Three decisions I guessed at, flagged so you can overrule them before implementation.

Human onlyI read it as a review-provenance filter and moved it beside coverage. If it means something else, it goes back with Runtime and Config.
Second Focus dropdownI assumed subsystem, since the status bar counts 35 of them. If it is risk tier or selection tier, R5 needs a third combo and Scope grows to four rows.
Tags vs BranchesThe web form has a Tags/Branches switch that the ribbon does not. I would put it as a two-state toggle inside the R3 field's left label, so the label itself reads either Branch or Tag.
