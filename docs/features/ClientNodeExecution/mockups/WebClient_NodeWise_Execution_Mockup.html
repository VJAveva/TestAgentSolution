WebClient — Node-Wise Execution every runnable node has its own trigger, like the WPF app
The gap this closes: today the WebClient only exposes the root trigger — an engineer must re-run the whole pipeline to test one fix. This adds a Run control on every runnable node (root, action group, single action, template action), so an engineer debugging can run just the node they're working on. Same RBAC: granted the pipeline = can run any node in it.

How it works — matching the WPF app

Every runnable node gets a Run control. Root, action group, single action, template action — same as the WPF tree.
Runs the node in isolation. A group runs its own actions; a single action runs just itself. Nothing before or after.
Optional Initialize. Because a node may need its parameters loaded, the confirm offers "+ its Initialize" when the node sits under one.
Same RBAC. If you're granted the pipeline, you can run any node in it — no separate permission. Locked pipelines still block.
Uses the pipeline's build by default (the effective build), shown in the confirm so there's no surprise.
Feeds the same live log as a full run — the node-run streams into Execution exactly like a root trigger, just scoped.
