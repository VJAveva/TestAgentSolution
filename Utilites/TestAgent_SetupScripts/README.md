# TestAgent Setup Scripts

Node preparation, diagnostics and deployment helpers for TestAgentSolution.

All scripts are ASCII-only with CRLF line endings, run non-interactively, and support
`-WhatIf` wherever they change state. Scripts that change a node report what they would
do before doing it.

**Published to:** `C:\TestAgentScripts` on the controller and every agent. This is
deliberately outside `C:\TestAgentService` and `C:\TestControllerService` so a
`robocopy /MIR` deployment never touches it.

## Environment facts these scripts assume

| Thing | Value |
|---|---|
| Controller gRPC | TCP **5100** (agents -> controller: register, heartbeat, events) |
| Controller HTTP | TCP **5200** (REST + SignalR for the React client) |
| Agent gRPC | TCP **5200** (controller -> agent: command dispatch), plaintext **h2c**, so Kestrel must be pinned to HTTP/2 |
| Agent install dir | `C:\TestAgentService` |
| Controller install dir | `C:\TestControllerService` |
| Agent launch | Scheduled task **"TestAgentGrpc Interactive"** (NOT a Windows service) |
| Minimum .NET runtime | **10.0.12** (ASP.NET Core + Windows Desktop) |

## Scripts

| Script | When to use it | Example |
|---|---|---|
| `Prepare-ControllerNode.ps1` | Full controller build-out: IIS + ANCM, .NET runtimes, firewall, run-as account, `appsettings.json`, starter `WatchList.xml`. Run once per controller. | `.\Prepare-ControllerNode.ps1 -ControllerPort 5100` |
| `Setup-AgentNode.ps1` | Full agent build-out: firewall (all profiles), Block-rule cleanup, WinRM, HTTP.sys reservation, `appsettings.json` with the h2c Kestrel pin. Run once per agent. | `.\Setup-AgentNode.ps1 -ControllerAddress http://JVGR22:5100 -WhatIf` |
| `Setup-DisplayNode.ps1` | Prepares a monitoring box running the WPF Dashboard. Outbound rules only. | `.\Setup-DisplayNode.ps1 -AgentIPs 10.48.190.60` |
| `Configure-AgentTaskRecovery.ps1` | Make the agent scheduled task restart itself after a crash and never be killed by a scheduler time limit. | `.\Configure-AgentTaskRecovery.ps1 -ComputerName JVGR1 -Apply` |
| `Test-NodeConnectivity.ps1` | First thing to run when anything looks wrong. PASS/FAIL per node for ping, DNS, SMB, ports both directions, WinRM, firewall, .NET version, registration. Read-only. | `.\Test-NodeConnectivity.ps1 -ReportPath C:\Temp\fleet.json` |
| `Diagnose-Http2Protocol.ps1` | The agent is up but the controller reports `HTTP_1_1_REQUIRED` (0xd). Confirms whether the endpoint really negotiates h2c. | `.\Diagnose-Http2Protocol.ps1 -AgentHost JVGR1` |
| `Deploy-WebToIIS.ps1` | Publish an already-built WebApi + WebClient folder into IIS on the controller. Does not build. | `.\Deploy-WebToIIS.ps1 -SitePort 8080 -WhatIf` |
| `Run-AgentSetup.bat` | Double-click wrapper for `Setup-AgentNode.ps1`. Edit the values at the top first. | right-click -> Run as administrator |
| `Run-ControllerSetup.bat` | Double-click wrapper for `Prepare-ControllerNode.ps1`. | right-click -> Run as administrator |
| `Run-DisplaySetup.bat` | Double-click wrapper for `Setup-DisplayNode.ps1`. | right-click -> Run as administrator |
| `Run-NodeConnectivity.bat` | Double-click wrapper for `Test-NodeConnectivity.ps1`. | right-click -> Run as administrator |
| `Invoke-NodeCleanup.ps1` | Node housekeeping: prunes old logs/dumps, trims backup sets, reports health. Dry run unless `-Apply`. Never stops the controller. | `.\Invoke-NodeCleanup.ps1 -Role Agent` |
| `fleet-inventory.json` | The protected-state lists (`preserveFiles` / `preserveFolders`). Published next to the cleanup script so it reads the real list instead of its embedded fallback. | n/a - data file |

Set `TCSETUP_NOPAUSE=1` to stop the `.bat` wrappers pausing at the end, for unattended use.

`Invoke-NodeCleanup.ps1` and `fleet-inventory.json` are published from `deploy\` in the repo. The
inventory is the single source of truth for the preserve lists; the copies embedded in
`Invoke-NodeCleanup.ps1` and `New-NodeManifest.ps1` are generated by `deploy\Sync-PreserveList.ps1`
and enforced by `deploy\Invoke-NodeCleanup.Tests.ps1`. Edit the inventory, never the embedded block.

## What replaced what

| Retired script (now in `_archive\`) | Replaced by | Why |
|---|---|---|
| `Configure-AgentRecovery.ps1` | `Configure-AgentTaskRecovery.ps1` | Configured Windows **service** recovery via `sc.exe`. The fleet runs the agent as a scheduled task, so it targeted a service that exists on no node and silently did nothing. |
| `Setup-ControllerNode.ps1` | `Prepare-ControllerNode.ps1` | Strict subset. Also defaulted `InstallDir` to the wrong path (`C:\TestAgentSolution\Controller`). |
| `Test-TestAgentNetwork.ps1` | `Test-NodeConnectivity.ps1` | Merged into the single PASS/FAIL diagnostic. |
| `Diagnose-AgentPort.ps1` | `Test-NodeConnectivity.ps1` | Port-ownership check folded into the `APORT` column. Also contained 78 non-ASCII characters. |
| `Run-NetworkDiagnostic.bat` | `Run-NodeConnectivity.bat` | Wrapper for the merged diagnostic. |
| `PublishWeb.ps1` | repo root `PublishWeb.ps1` | Two copies had diverged. Building belongs at the repo root; this folder keeps only the node-side `Deploy-WebToIIS.ps1`. |

`_archive\` is kept for reference and is **not** published to nodes.

## Typical order

1. `Prepare-ControllerNode.ps1` on the controller.
2. `Setup-AgentNode.ps1` on each agent.
3. Copy the published binaries to the install folders.
4. `Configure-AgentTaskRecovery.ps1 -Apply` once the scheduled task exists.
5. `Test-NodeConnectivity.ps1` to confirm the whole fleet is green.
